# ADR012：按内容复用分块向量

新快照仍完整构建图与分块，但只编码内容缓存未命中的分块。缓存key是完整模型输入文本和模型文件/版本、token预算、分块策略、推理库与设备身份；不包含snapshot ID。源码或完整上下文变化使key变化，未变文本可以跨SHA复用。新bundle仍保存新snapshot的chunk ID、父符号、范围及证据，旧snapshot身份不会随向量一同复制。

每行float32向量在SQLite中带SHA256，加载检验checksum、非空和finite；不同维度在组装时拒绝。成功完成query/reranker之后才写入派生row cache并发布bundle。既有已校验bundle可以填充row cache用于后续更新。损坏数据不静默降级。

这是向量编码增量，不是依赖图最小失效：解析仍按原实现复用未变AST并重解所有引用，分块仍全量重建。尚不能仅凭编码复用数量宣称端到端2倍加速。真实对照记录会同时报告全量/增量向量误差、排名、编码数量和实际耗时；没有正式质量金标。

真实Click-02对照（incremental-retrieval-run-042fc964ccac4749907ff9e8bf5ed71d.json）：3258块复用3251/编码7，增量49.05秒、全量163.55秒（单次3.33倍）；排名一致，向量最大绝对差1.313e-7。运行时同机还有Docker复核，样本仅一条，不能推广为稳定端到端2倍结论。两侧语料仍partial。
