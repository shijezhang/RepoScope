# ADR 006：按完整证据单元打包模型上下文

状态：2026-09-10夜间实现并验证，仍有剩余边界。

过去将整份context和schema的UTF-8字节数加2000作为保守准入，但不能在剩余预算下降时取舍信息；两个已有证据片段会与重复的初始符号摘要竞争预算，导致提前停止。

现在provider和controller共用消息序列化，紧凑JSON保留相同数据含义。准入上界包含system和context实际UTF-8字节数、600生成上限及512条消息封装余量，不提升12000累计预算。选择优先级为最新完整工具结果、限制、其他最近结果、初始符号摘要；未选项有明确计数。完整原始事实仍在Store，代码字符串不会按字符裁断。

回归测试验证原失败剩余预算下可以准入最近完整证据、过大证据整体省略、关键任务本身过大时仍停止，以及请求与计费上界使用相同序列化。

独立真实开发实验见benchmarks/results/agent-night-0230.json：fixture-01从零验证推进到一次run_tests，但后续模型收尾仍受剩余预算限制；fixture-04仍失败，本次诊断明确为length且JSON为空。没有增加输出token上限或自动补请求，没有覆盖原失败。数据范围在执行后再次核验。

这些是两个未复核开发fixture的功能观察，不构成正式B4/B3质量或性能提升结论。后续应减少不可再执行工具的schema开销，并基于实际诊断改进短结构化输出；不能靠扩额或隐藏失败满足验收。
