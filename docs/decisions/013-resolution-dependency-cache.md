# ADR013：文件级引用依赖失效（parser v4）

v3只复用AST，引用仍全量重解。v4为每个文件保存引用解析结果及实际访问的导出依赖。依赖指纹涵盖目标符号稳定身份/装饰器标记、包前缀的遮蔽绑定、匹配的重导出定义及缺失目标；导入失败后的父模块回退也记录直接查找依赖。

缓存以本文件完整源码和parser版本为key。依赖未变时恢复关系与unknown记录，并把稳定的path/qualname/kind/重复序号身份重新绑定到当前snapshot的symbol ID。函数体改变但导出不变时，不要求调用者重解；删除、重命名、新增原本缺失的目标、装饰器变化、重导出/包前缀遮蔽则失效。CONTAINS与符号本身仍从当前快照重建，不复制旧证据hash。

缓存带内容hash，损坏直接拒绝。回调取消检查保留。版本升级到ast312-resolver-v4，v3历史快照和缓存不覆盖；版本变化使旧coverage在新snapshot下自然失效，不能重标为有效。

这是文件级、按解析器已观测依赖的最小失效，不是表达式级理论最小。文件自身任意源码变化仍使该文件失效；目标解析规则继续保守处理动态关系，不增加确定边。

验证：13项针对性反例含缺失目标新增、导出删除/更名、装饰器、同名重复定义、重导出循环/遮蔽、包前缀遮蔽和缓存损坏；全量138项通过。12条原有变更v4全量/增量语义hash全部一致；两个独立历史修复也一致。一般单文件变更只重解1文件，Click复用69、HTTPX复用59；删除/改名则重解2个fixture文件。

实际端到端耗时未稳定改善：部分case增量更快，部分更慢。Git读取、符号重建与缓存检查仍有成本；保留index-consistency-v4.json原始时延，不据复用数量宣称稳定2倍。
