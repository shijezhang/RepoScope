# ADR014：同名导入覆盖直接导出（parser v5）

依赖缓存收尾检查发现旧解析边界：模块先定义work，后用from target import work覆盖名称；其他模块调用该导出时，原export_target仍优先返回模块内的旧定义，并标resolved。新增反例在v4实际失败，不能把这样的结果缓存为可靠目标。

v5在导出路径检查模块级定义与同名导入冲突。由于当前解析器不证明条件分支和绑定顺序，冲突保持unknown；不猜测旧定义或某个导入一定是运行时目标。类名被导入覆盖时，其成员路径也检查同一根绑定。

依赖指纹同步包含包前缀根定义与同名导入，确保“新加一个同名导入”会使未变消费者失效。parser和Snapshot默认版本升级为ast312-resolver-v5，避免复用v4关系缓存或混用旧coverage绑定；历史v3/v4快照不覆盖。

新增两个反例覆盖直接函数导出及已缓存的类成员查找。最终15项针对性解析缓存测试、140项全量测试通过；12条原有变更与2条历史修复均完成v5全量/增量一致性。原v4测试、探针和失败证明作为历史阶段记录保留。
